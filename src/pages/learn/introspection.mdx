# イントロスペクション

<p className="learn-subtitle">GraphQLスキーマに関する情報をクエリする方法を学ぶ</p>

GraphQLスキーマがサポートする機能について情報を尋ねることは、しばしば有用です。GraphQLは、[イントロスペクションシステム](https://spec.graphql.org/draft/#sec-Introspection)を使用してこれを行うことを可能にします。

イントロスペクションクエリは、GraphQL APIのスキーマについて学ぶことを可能にする特別な種類のクエリであり、GraphQL開発ツールを強化するのにも役立ちます。このページでは、基盤となるスキーマの型、フィールド、説明について詳しく学ぶために、さまざまなクエリを実行する方法を学びます。

## 型名のイントロスペクション

[スキーマと型のページ](/learn/schema/)で、イントロスペクションの例をすでに見ました。Union型を返すフィールドをクエリする場合、検索クエリによって返される異なる型の名前の文字列値を取得するために、選択セットに`__typename`メタフィールドを直接含めました。この例をもう一度見てみましょう：

```graphql
# { "graphiql": true }
query {
  search(text: "an") {
    __typename
    ... on Character {
      name
    }
    ... on Starship {
      name
    }
  }
}
```

`__typename`フィールドをGraphQL APIに明示的に追加していませんでした—GraphQL仕様では、GraphQL実装によってクライアントに提供される必要があると述べています。このフィールドは、基盤となる出力型としてオブジェクト、インターフェース、またはUnion型を持つ任意のフィールドに対してクエリできます。

## スキーマのイントロスペクション

イントロスペクションは、クエリで型名を提供する以上のことができます。GraphQL APIの型システムを設計した場合、利用可能な型をすでに知っている可能性があります。しかし、設計していない場合は、`query`ルート操作型で常に利用可能な`__schema`フィールドをクエリすることで、GraphQLに尋ねることができます。

それでは、スター・ウォーズスキーマで利用可能な型を尋ねてみましょう：

```graphql
# { "graphiql": true }
query {
  __schema {
    types {
      name
    }
  }
}
```

すごい、たくさんの型があります！それらは何でしょうか？グループ化してみましょう：

- 型システムで定義した型：`Query`、`Mutation`、`Character`、`Human`、`Episode`、`Droid`、`LengthUnit`、`FriendsConnection`、`FriendsEdge`、`PageInfo`、`Review`、`ReviewInput`、`Starship`、および`SearchResult`
- 型システムが提供した組み込みスカラー：`Boolean`、`Float`、`ID`、`Int`、および`String`
- イントロスペクションシステムの一部である二重アンダースコアで始まる型：`__Schema`、`__Type`、`__TypeKind`、`__Field`、`__InputValue`、`__EnumValue`、`__Directive`、および`__DirectiveLocation`

それでは、利用可能なクエリを探索するための良い出発点を見つけようとしましょう。型システムを設計したとき、すべてのクエリが開始する型を指定しました。イントロスペクションシステムにそれについて尋ねてみましょう：

```graphql
# { "graphiql": true }
query {
  __schema {
    queryType {
      name
    }
  }
}
```

結果は、[型システムセクション](/learn/schema/#type-system)で述べたことと一致しています—`Query`型が開始点であるということです。ここでの命名は慣例によるものであることに注意してください。`Query`型に別の名前を付けることもでき、クエリの開始型として指定していれば、ここで返されていたでしょう。ただし、`Query`と命名することは有用な慣例です。

1つの特定の型を調べることは、しばしば有用です。`Droid`型を見てみましょう：

```graphql
# { "graphiql": true }
query {
  __type(name: "Droid") {
    name
  }
}
```

しかし、Droidについてもっと知りたい場合はどうでしょうか？例えば、それはインターフェース型ですか、それともオブジェクト型ですか？

```graphql
# { "graphiql": true }
query {
  __type(name: "Droid") {
    name
    kind
  }
}
```

`kind`は`__TypeKind`列挙型を返し、その値の1つは`OBJECT`です。代わりに`Character`について尋ねた場合、それがインターフェース型であることがわかります：

```graphql
# { "graphiql": true }
query {
  __type(name: "Character") {
    name
    kind
  }
}
```

オブジェクト型にとって、利用可能なフィールドを知ることは有用です。それでは、イントロスペクションシステムに`Droid`について尋ねてみましょう：

```graphql
# { "graphiql": true }
query {
  __type(name: "Droid") {
    name
    fields {
      name
      type {
        name
        kind
      }
    }
  }
}
```

これらは、`Droid`で定義したフィールドです！

`id`は少し奇妙に見えます。型の名前がありません。これは、`NON_NULL`の種類の_ラッパー型_であるためです。そのフィールドの型で`ofType`をクエリすると、そこに`ID`型が見つかり、これが非nullIDであることがわかります。

同様に、`friends`と`appearsIn`の両方に名前がありません。これらは`LIST`ラッパー型であるためです。それらの型で`ofType`をクエリすると、リスト内の型がわかります：

```graphql
# { "graphiql": true }
query {
  __type(name: "Droid") {
    name
    fields {
      name
      type {
        name
        kind
        ofType {
          name
          kind
        }
      }
    }
  }
}
```

ツールにとって特に有用なイントロスペクションシステムの機能で終わりましょう。システムにドキュメントを尋ねてみましょう：

```graphql
# { "graphiql": true }
query {
  __type(name: "Droid") {
    name
    description
  }
}
```

上記で示したように、イントロスペクションを使用して型システムに関するドキュメントにアクセスし、ドキュメントブラウザーやリッチなIDEエクスペリエンスを作成できます。

これはイントロスペクションシステムの表面をかすめただけです。列挙型の値をクエリしたり、別の型が実装するインターフェース型をクエリしたり、さらに多くのことができます。イントロスペクションシステム自体をイントロスペクションすることもできます。

コードで実装された仕様に準拠したGraphQLクエリイントロスペクションシステムの例を見るには、リファレンス実装の[src/type/introspection.ts](https://github.com/graphql/graphql-js/blob/e9b6b626f6f6aa379bb8f8c48df40d0c02a26082/src/type/introspection.ts)を参照してください。

## 本番環境でのイントロスペクション

イントロスペクションは、GraphQLの有用な機能であり、特にクライアント開発者とツールにとって有用です。しかし、独自のアプリケーション専用のAPIの場合、本番環境では通常必要ありません—必要な操作は通常、ビルド時にこれらのアプリケーションに組み込まれるため、ランタイムイントロスペクションは不要です。

APIの攻撃面を減らすために、本番環境でイントロスペクションを無効にすることは一般的です。これは、より広範なAPIセキュリティ戦略の一部であることが多く、認証と認可、操作の安全リスト（または、深度制限、幅制限、エイリアス制限、サイクル拒否、コスト分析などの代替保護の範囲）、実行タイムアウトなども含まれる場合があります。

## 次のステップ

イントロスペクションについて学んだことをまとめると：

- 型名は、`__typename`メタフィールドを使用して、オブジェクト、インターフェース、またはUnion型のフィールド選択セットでクエリできます
- GraphQLスキーマの要素に関する情報は、`query`ルート操作型の`__schema`フィールドを使用してクエリできます
- イントロスペクションは、本番環境ではしばしば無効にされます

GraphQL型システム、APIからデータをクエリする方法、リクエストのライフサイクルがどのように見えるかを探索したので、[ベストプラクティス](/learn/best-practices/)セクションに進んで、本番環境でGraphQLを実行する方法について詳しく学んでください。
