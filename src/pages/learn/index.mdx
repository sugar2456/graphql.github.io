# GraphQL入門

<p className="learn-subtitle">GraphQLについて学び、その仕組みと使い方を理解する</p>

GraphQLはAPIのためのクエリ言語であり、データに対して定義した型システムを使用してクエリを実行するサーバーサイドランタイムです。[GraphQL仕様](https://spec.graphql.org/)は2015年にオープンソース化され、以降、様々なプログラミング言語で実装されています。GraphQLは特定のデータベースやストレージエンジンに依存せず、既存のコードとデータによって支えられています。

<Callout type="info">すでにGraphQLに精通しており、GraphQLサービスの構築方法に関するドキュメントを読みたい場合は、[多くの異なる言語](/community/tools-and-libraries/?tags=server)でGraphQLを実装するのに役立つライブラリがあります。また、[クライアントアプリケーションが既存のGraphQL APIをクエリできる](/community/tools-and-libraries/?tags=client)ライブラリも多数利用可能です。</Callout>

## 型システムでAPIを記述する

GraphQLサービスは、[型とそのフィールドを定義](/learn/schema/)し、各フィールドに対して[必要なデータを提供する](/learn/execution/)関数を記述することで作成されます。例えば、ログインしているユーザーの名前を教えてくれるGraphQLサービスは次のようになります：

```graphql
type Query {
  me: User
}

type User {
  name: String
}
```

各型の各フィールドに対する関数と共に：

```js
// `Query`型の`me`フィールドのリゾルバ
function resolveQueryMe(_parent, _args, context, _info) {
  return context.request.auth.user;
}

// `User`型の`name`フィールドのリゾルバ
function resolveUserName(user, _args, context, _info) {
  return context.db.getUserFullName(user.id);
}
```

上記の例では、`Query`型の`me`フィールドにデータを提供する関数は、リクエストを行った認証済みユーザーに関する情報を使用しますが、`User`型の`name`フィールドは、そのユーザーのIDを使用してデータベースからフルネームを取得することで値が設定されます。

## 必要なものだけをクエリする

GraphQLサービスが実行されると（通常はWebサービスのURL上で）、クライアントから[GraphQLクエリ](/learn/queries/)を受け取り、検証して実行できます。サービスはまずクエリをチェックして、APIに定義された型とフィールドのみを参照していることを確認し、次に提供された関数を実行して結果を生成します。

例えば、次のクエリは：

```graphql
{
  me {
    name
  }
}
```

次のJSONの結果を生成できます：

```json
{
  "data": {
    "me": {
      "name": "Luke Skywalker"
    }
  }
}
```

シンプルなクエリでさえ、GraphQLを非常に強力にする主要な機能のいくつかを見ることができます。クライアントは必要なデータの構造を反映するクエリをAPIに対して実行し、期待される形式でそのデータだけを単一のリクエストで受け取ることができます。そして、どの基盤となるデータソースがそれを提供したかを気にする必要はありません。

## バージョニングなしでAPIを進化させる

クライアントの要件は時間とともに変化し、GraphQLは異なるAPIバージョンを管理するオーバーヘッドなしに、それらのニーズに応じてAPIを進化させることができます。例えば、新しい機能でより具体的な名前の値が利用可能である必要がある場合、`User`型は次のように更新できます：

```graphql
type User {
  fullName: String
  nickname: String
  name: String @deprecated(reason: "Use `fullName`.")
}
```

クライアントツールは開発者に新しいフィールドの使用を促し、非推奨の`name`フィールドの使用を削除します。フィールドはもはや使用されていないと判断されたら削除できます。それまでの間、GraphQLは期待通りにデータを提供し続けます。

## 試してみよう！

GraphQLを学ぶ最良の方法は、クエリを書き始めることです。このガイド全体で使用されているクエリエディタは**インタラクティブ**なので、`hero`オブジェクトに`id`と`appearsIn`フィールドを追加して、更新された結果を確認してみてください：

```graphql
# { "graphiql": true }
{
  hero {
    name
    # ここに追加のフィールドを追加してください！
  }
}
```

<Callout type="info">
このガイドの例は[改変版のSWAPI GraphQLスキーマ](https://github.com/graphql/graphql.github.io/blob/source/src/components/interactive-code-block/swapi-schema.tsx)に基づいています。これらのクエリは説明を目的として設計されているため、2つのスキーマ間の違いにより、完全版のSWAPI GraphQL APIでは実行されません。[完全版のAPIはこちらで試すことができます。](https://graphql.org/swapi-graphql/)
</Callout>
